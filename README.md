1. 프로젝트 소개
종합 골프 정보 및 커뮤니티 기능을 지원하는 웹서비스.

프로젝트의 이름은 BirdieBuddy로 결정.

2. 주요 기능
구분	내용
유저	회원가입, 로그인, 이메일 인증, 계정 찾기, 정보 변경 및 탈퇴
커뮤니티	게시글과 댓글 작성 및 수정, 삭제, 검색, 말머리, 추천과 비추천, 공지, 인기글
유저 블로그	유저별 게시글, 댓글 목록 조회
골프장	현재 위치 기반 지도, 골프장 이름순, 거리순 조회
뉴스	네이버 골프 뉴스의 제목, 짧은내용 표시 및 원문 연결
영상	관리자가 선별한 유튜브 영상 공유
관리자	회원 제재, 게시글·댓글 삭제, 공지·영상 관리
비회원은 게시글, 댓글, 뉴스, 영상을 조할 수 있음, 다만 추천과 비추천 게시글과 댓글 작성은 불가함.

추후 모바일 호환, 대댓글, 활동 목록 숨김, 그린피 비교(더미데이터), 서버 모니터링은 유지 보수 및 업데이트 시에 구현하는 것을 검토중임.

3. 기술 구성
구분	기술
개발 도구	IntelliJ IDEA, MobaXterm
Front-End	React
웹 서버	Nginx
Back-End	Kotlin, Spring Boot, Spring Security, JPA
데이터베이스	MySQL
배포 환경	AWS
버전관리	Git, Github
Docker는 추후 활용 예정.

4. 서버 구성 계획
사용자
   ↓ HTTPS
WEB 서버 — Nginx / React 파일 제공
   ↓
WAS A(주 서버) / WAS B(대기 서버)
   ↓
DB서버(MYSQL) 매일 0시 백업
웹 요청 전달, 서비스 로직, 데이터 저장 역할을 분리.
WAS-A 장애 시 WAS-B로 전환하는 구성이며 원활한 서비스 제공 및 장애대응에 초점을 맞춤.
배포 직후에는 이전 버전을 대기 서버에 유지, 검증 후 같은 버전으로 동기화.
DB는 한국시간 매일 00시에 백업하고 최근 7일분을 보관하는 안으로 진행.
WEB과 DB는 한 대씩 운영, 장애 시 재구축, 복원으로 대응.
HTTPS, 서버 접근 제한, 비밀번호 해시 저장, 비밀키 분리를 적용.
WEB서버에 서버 모니터링 기능 탑재 검토
