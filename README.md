# Hey!Birdie 프로젝트 계획안 초안

> 골프 커뮤니티와 주변 골프장 정보, 뉴스, 레슨 영상을 한곳에서 제공하는 PC 웹 서비스
> 

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | Hey!Birdie |
| 주제 | 종합 골프 커뮤니티 |
| 개발 기간 | 13주 |
| 지원 환경 | PC 웹 |

골프에 관심 있는 사용자가 정보를 공유하고, 현재 위치를 기준으로 골프장을 확인하며, 관련 뉴스와 영상을 찾아볼 수 있는 서비스를 개발한다.

초기에는 핵심 기능을 완성하고, 테스트와 운영 결과를 바탕으로 기능을 개선한다.

## 2. 개발 목표

- Kotlin과 Spring Boot를 활용한 백엔드 개발 역량 강화.
- React를 활용한 사용자 화면 구현 및 백엔드 연동.
- 회원 인증·권한 관리와 관계형 데이터베이스 설계 경험.
- 외부 API 연동과 오류 처리 경험.
- AWS 서버 구축, 배포, 장애 전환, 백업·복원 경험.
- 구현 과정과 문제 해결 내용을 기록해 포트폴리오로 정리.

## 3. 사용자와 권한

| 사용자 | 주요 권한 |
| --- | --- |
| 비회원 | 게시글·댓글·뉴스·영상 열람 |
| 회원 | 글·댓글 작성, 본인 작성물 수정·삭제, 추천·비추천, 개인정보 변경 |
| 관리자 | 회원 기능 + 공지 작성, 회원 제재, 게시글·댓글 삭제, 영상 관리 |

관리자 계정은 일반 회원가입과 분리해 사전에 생성한다. 권한은 화면 표시와 서버 요청 처리 양쪽에서 확인한다.

## 4. 주요 구현 기능

### 4.1 홈

- 게시판·뉴스·영상 미리보기와 더보기.
- 비로그인 상태에서는 로그인 창 표시.
- 로그인 후 회원 대시보드 표시.
- 현재 위치 기반 골프장 지도와 목록 제공.
- 공통 메뉴를 통해 주요 페이지로 이동.

### 4.2 회원 및 인증

- 회원가입, 로그인, 로그아웃.
- ID 중복 확인 및 이메일 인증.
- 이메일 인증을 통한 ID 찾기와 비밀번호 재설정.
- 비밀번호 재확인 후 개인정보 변경.
- ID·비밀번호·이메일·닉네임 변경.
- 회원 탈퇴.

| 항목 | 정책 |
| --- | --- |
| ID | 영문·숫자 4~16자, 영문 최소 1자 포함하는 안을 기준으로 최종 확정 |
| ID 대소문자 | 구분하는 방향으로 설계 |
| 비밀번호 | 재입력 검증, 특수문자 허용. 길이·필수 조합은 개발 전 확정 |
| 닉네임 | 중복 허용 |
| 주소 | 수집하지 않음 |
| 회원 식별 | 변경되지 않는 내부 회원 식별자 사용 |

탈퇴 후 게시글·댓글은 유지하고, 해당 회원의 블로그 접근은 차단한다. 개인정보 삭제·보관 정책은 작성물 유지 정책과 별도로 정한다.

### 4.3 커뮤니티

- 전체글·인기글·공지 목록.
- 자유·질문·후기 등의 말머리.
- 제목 또는 작성자 닉네임 검색.
- 페이지 번호를 통한 목록 이동 및 검색 조건 유지.
- 공지는 전체글 상단에도 고정.
- 본인 게시글·댓글 수정 및 삭제.
- 게시글 삭제 시 우선 DB의 삭제 상태로 처리하고 화면에서 숨김.
- 에디터를 활용한 글 작성.
- 이미지 및 파일당 최대 50MB 동영상 업로드.

추천 점수는 `추천 수 − 비추천 수`로 계산하며, 최종 점수 5 이상인 글을 인기글로 표시한다.

- 로그인 회원만 투표 가능.
- 자기 게시물 투표 허용.
- 추천 수와 비추천 수는 각각 저장.
- 취소 기능은 제공하지 않음.
- 반대 투표로 변경하는 방식과 양쪽 투표를 각각 허용하는 방식 중 최종 정책 확정 필요.

### 4.4 유저 블로그

- 작성자 이름 클릭 시 해당 회원의 블로그로 이동.
- 회원이 작성한 게시글·댓글 목록 제공.
- 닉네임이 같아도 내부 회원 식별자로 구분.
- 블로그 활동 목록 숨기기는 후속 기능으로 검토.
- 활동 목록을 숨겨도 게시판과 작성자 검색에는 작성물이 유지됨.

### 4.5 주변 골프장

- 브라우저 위치 권한을 요청해 현재 위도·경도 확인.
- 네이버 지도에 사용자 위치와 골프장 표시.
- 골프장 이름순·직선거리순 정렬.
- 초기 목표는 필드 골프장 정보 제공.
- 위치 권한 거부·조회 실패 시 기본 지역 표시를 적용하는 안 검토.
- 골프장 데이터 확보 및 필드 골프장 분류 방식 검토.
- 그린피 가격 비교는 초기 개발 범위에서 제외.

지도 표시와 골프장 목록 확보는 별도 기능으로 설계한다.

### 4.6 뉴스

- 네이버 뉴스 검색 API로 골프 관련 검색 결과 조회.
- 기본 이미지, 제목, API 요약문 최대 100자 표시.
- 제목·요약 검색 및 페이지 이동.
- 기사 클릭 시 API에서 제공하는 외부 기사 링크로 이동.
- 데이터 보관 조건을 확인하고 중복 방지·갱신 정책 수립.

### 4.7 영상

- 관리자가 선별한 유튜브 영상 등록 및 공개.
- 썸네일·제목 클릭 시 영상으로 이동.
- 채널명 클릭 시 해당 채널로 이동.
- 등록 영상의 제목·채널명 검색.
- 영상 파일 대신 영상 ID와 관련 정보 활용.
- API 정보 갱신 및 삭제·비공개 영상 처리.

### 4.8 관리자

- 회원 검색.
- 일시·영구 정지 및 해제.
- 제재 사유·기간 기록.
- 게시글·댓글 삭제.
- 공지 작성 및 선별 영상 관리.

정지 회원은 로그인을 제한한다. 이미 로그인된 경우에도 글·댓글 작성과 투표 요청 시 제재 여부를 확인한다.

## 6. 초기 서버 구성

```
사용자 브라우저
       ↓ HTTPS
APP 서버 — Nginx / React 빌드 파일
       ↓
 ┌────────────┬────────────┐
 │ WAS A      │ WAS B      │
 │ 주 서비스  │ 대기 서버  │
 └────────────┴────────────┘
       ↓
    MySQL
       ↓
매일 00시 백업 저장소
```

- 사용자는 도메인을 통해 APP 서버에 접속.
- Nginx가 화면을 제공하고 API 요청을 WAS로 전달.
- 평상시 WAS A 사용, 장애 조건 충족 시 WAS B로 전환.
- WAS A/B는 공용 DB와 업로드 파일 저장소 사용.
- 로그인 상태가 서버 전환 후에도 유지되도록 설계.
- APP과 DB는 초기 구성에서 단일 장애 지점으로 남음.
- 별도 백업 DB 서버의 상시 운영 여부는 비용을 검토해 결정.

## 7. 배포와 복구

### 애플리케이션 배포

1. 기존 버전과 새 버전의 DB·API 호환성 확인.
2. 배포 전 필요한 백업 수행.
3. 주 WAS에 새 버전 배포.
4. 대기 WAS에는 이전 버전을 잠시 유지.
5. 정상 동작 검증 후 대기 WAS도 같은 버전으로 변경.
6. 이전 배포 결과물은 버전별로 보관.

애플리케이션 버전 복귀와 DB 데이터 복구는 별도로 처리한다.

### DB 백업

- 매일 한국시간 00시 백업 시작.
- 날짜별로 최근 7일분 보관하는 안을 적용.
- DB 구조 변경·대량 수정 전 추가 백업.
- 백업 성공·실패 기록.
- 실제 복원 테스트 수행.
- 일일 백업 사이의 데이터 손실 가능성과 복원 소요시간을 한계로 명시.

## 8. 기본 보안 및 운영

- HTTPS 적용.
- WAS는 APP에서, DB는 WAS에서만 접근하도록 제한.
- 관리자 접속 경로 제한 및 AWS 계정 MFA 적용.
- 비밀번호 해시 저장.
- 비밀키·DB 접속 정보를 소스와 분리.
- 서버에서 회원·작성자·관리자 권한 검증.
- 로그인·인증메일·글·댓글 요청 빈도 제한.
- 게시글 HTML 정제 및 업로드 파일 검증.
- 이용약관·개인정보 안내와 필요한 동의 화면 준비.
- 오류 로그, 서버 상태, 백업 결과 확인.

초기에는 기본 모니터링을 적용하고, 이후 별도 관리 서버 또는 모니터링 서비스를 검토한다.

## 12. 검증 및 기록 방법

기능 구현 여부뿐 아니라 실제 동작과 실패 상황을 확인한다.

- 다른 회원의 글을 수정·삭제할 수 없는지.
- 추천 중복 요청에도 점수가 올바른지.
- 정지 회원의 기존 로그인 상태에도 제한이 적용되는지.
- 위치 권한 거부와 외부 API 장애를 처리하는지.
- WAS 중단 후 서비스가 전환되는지.
- 백업 데이터로 실제 복원이 가능한지.

개발 과정은 **문제 → 선택한 방법과 이유 → 검증 결과 → 남은 한계** 순서로 기록한다.
